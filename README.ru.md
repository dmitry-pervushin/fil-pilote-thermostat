# Fil Pilote Thermostat

[Français](README.md) · [English](README.en.md) · [Русский](README.ru.md)

Локальный термостат для Home Assistant: управление электрическим радиатором через **интерфейс fil pilote с двумя реле** и внешний датчик температуры. Настройка через интерфейс HA; существующие конфигурации YAML импортируются автоматически.

Требуется **Home Assistant 2026.11 или новее**. Проверки выполняются на Core 2026.11.1 и Python 3.14. Основная документация — на французском, также доступны английский и русский. Язык формы настройки зависит от профиля HA.

## Установка

**Настройка через YAML не требуется.** Рекомендуемый способ — интерфейс Home Assistant: выберите реле и датчик, затем меняйте параметры без редактирования `configuration.yaml`.

1. Скопируйте `custom_components/fil_pilote_thermostat` в каталог конфигурации HA: `/config/custom_components/fil_pilote_thermostat/`.
2. Перезапустите Home Assistant.
3. Откройте **Настройки → Устройства и службы → Добавить интеграцию → Fil Pilote Thermostat**.
4. Выберите два реле и датчик комнатной температуры, затем задайте пределы и допуски.

Начиная с версии **1.1.1** термостат отображается на вкладке **Интеграции**, а не **Вспомогательные элементы (Helpers)**. Для существующей установки обновите компонент и перезапустите HA: настройки и идентификаторы сущностей сохранятся, пересоздавать термостат не нужно.

Реле могут быть сущностями `switch`, `light` или `input_boolean` с состояниями on/off. Датчик — сущностью `sensor`. Параметры меняются без перезапуска HA. Для замены самих реле нужно пересоздать интеграцию. При настройке через интерфейс повторное использование реле другим термостатом запрещено.

Проект доступен на [GitHub](https://github.com/dmitry-pervushin/fil-pilote-thermostat). Для добавления в HACS откройте **Пользовательские репозитории**, укажите URL этого репозитория и выберите категорию **Интеграция**. В стандартный каталог HACS проект не включён.

## Сигналы fil pilote

Сохранена таблица реле исходного компонента:

| Режим HA | Команда радиатору | S1 | S2 |
| --- | --- | --- | --- |
| `comfort` | Комфорт | off | off |
| `eco` | Эко | on | on |
| `away` | Защита от замерзания / Hors-gel | on | off |
| `sleep` | Остановка / Arrêt | off | on |

**Порядок S1 и S2 важен.** Перед включением нагрева проверьте соответствие таблицы своему интерфейсу. Это логические состояния реле, а не схема подключения сетевого напряжения. Предполагается уже установленный подходящий интерфейс fil pilote.

В режиме HVAC `heat` пресеты Comfort и Eco используют внешний датчик и гистерезис. Нагрев запрашивается при `цель − cold_tolerance`, остановка — при `цель + hot_tolerance`. Внутри диапазона предыдущий запрос сохраняется. В Eco радиатор может дополнительно снижать температуру своим внутренним регулятором.

Away постоянно передаёт защиту от замерзания; её температурный порог задаётся самим радиатором. Sleep постоянно передаёт остановку. HVAC `off` всегда запрашивает остановку, даже без исправного датчика. Выбор пресета не включает нагрев. При первой установке значения по умолчанию: **Off**, **Away** и **20 °C**, с учётом настроенных пределов.

На радиаторе нужен режим внешнего управления/программы/fil pilote. Его собственный термостат должен допускать желаемую температуру: fil pilote не обходит внутреннее ограничение. `hvac_action: heating` означает наблюдаемый сигнал Comfort/Eco, а не измеренную мощность и не подтверждение включения нагревательного элемента.

## Температура и восстановление

Все параметры конфигурации и допуски задаются в **°C**. Интерфейс climate и стандартные действия HA используют выбранные системные единицы с автоматическим преобразованием. Показания датчика в °C, °F и K переводятся в °C. Датчик без единиц считается датчиком °C.

После перезапуска или перезагрузки восстанавливаются целевая температура, HVAC и пресет. Необязательные `target_temp`, `initial_hvac_mode` и `initial_preset` **переопределяют сохранённые значения при каждом запуске/перезагрузке**. Оставьте их пустыми, чтобы сохранялись последние настройки пользователя. Некорректные сохранённые режимы игнорируются; недопустимая температура заменяется подходящим значением по умолчанию.

## Ошибки и диагностика

Отсутствующий, недоступный, нечисловой датчик, NaN или бесконечность делают термостат недоступным и вызывают запрос остановки. Недоступность реле обрабатывается аналогично. Компонент пытается выставить комбинацию остановки на доступных реле, но при неисправном или недоступном реле доставка полного сигнала не гарантируется.

`sensor_timeout` задаёт максимальное время с последнего сообщения датчика в секундах. По умолчанию `0` отключает проверку — это подходит датчикам, сообщающим только об изменении значения. Проверка выполняется при изменениях состояния и раз в 60 секунд; обнаружение просрочки может занять дополнительную минуту.

Команды ждут завершения действий реле, выполняются последовательно и не отправляются повторно без необходимости. Каждую минуту выполняется повторная попытка после ошибок и сверка состояния. Изменения реле также вызывают коррекцию: управляйте отоплением через сущность climate. Ошибка команды делает термостат недоступным до успешной сверки. При выгрузке подписки и таймеры удаляются, последний физический сигнал сохраняется.

Атрибуты диагностики: `pilot_mode`, `requested_pilot_mode`, `requested_hvac_mode`, `requested_preset_mode`, `heater_s1`, `heater_s2`, `sensor_entity_id`, `command_failed`. HA скрывает атрибуты состояния недоступной сущности; выгрузка диагностики интеграции работает и во время неисправности.

## YAML (необязательно)

Если термостат уже добавлен через интерфейс, пропустите этот раздел: добавлять блок YAML не нужно.

**Начиная с версии 1.1.0 миграция YAML → UI выполняется автоматически.** Обновите компонент, оставьте существующий YAML-блок и перезапустите HA. Каждый термостат появится в **Настройки → Устройства и службы**, где затем можно менять его параметры.

Если `unique_id` отсутствовал, он назначается автоматически, устраняя предупреждение о невозможности управлять настройками сущности. Если идентификатор уже был, сохраняется он и запись реестра, включая пользовательское название, зону и иконку. Без прежнего `unique_id` идентификатор сущности по-прежнему определяется названием в YAML: например, `name: Bureau` даёт `climate.bureau`, если этот идентификатор свободен. Сохранённые цель и режим восстанавливаются, если их не переопределяют начальные параметры YAML.

После проверки интеграции и идентификатора сущности **можно удалить YAML-блок термостата**. Компонент не редактирует ваши файлы. Если блок останется, следующие запуски не создадут дубликаты и не перезапишут изменения из UI: **YAML читается только при первоначальном импорте**. Если те же реле уже принадлежат настроенному термостату, существующая интеграция сохраняется без повторного импорта. Не создавайте вторую интеграцию вручную перед миграцией.

Если прежняя конфигурация использовала °F, перед обновлением переведите цели, пределы и допуски в °C. Новый формат конфигурации всегда использует °C.

```yaml
climate:
  - platform: fil_pilote_thermostat
    name: Гостиная
    unique_id: living_room_fil_pilote
    heater_s1: switch.radiator_s1
    heater_s2: switch.radiator_s2
    target_sensor: sensor.living_room_temperature
    min_temp: 7
    max_temp: 30
    cold_tolerance: 0.3
    hot_tolerance: 0.3
    precision: 0.1
    sensor_timeout: 0
    # Необязательно: переопределять восстановленные значения при каждом запуске.
    # target_temp: 20
    # initial_hvac_mode: heat
    # initial_preset: comfort
```

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `heater_s1`, `heater_s2` | обязательны | Два разных реле |
| `target_sensor` | обязателен | Датчик комнатной температуры |
| `name` | Fil Pilote Thermostat | Название сущности |
| `unique_id` | необязателен | Прежний идентификатор сохраняется; при отсутствии назначается автоматически |
| `min_temp`, `max_temp` | 7 / 35 | Пределы цели в °C; минимум меньше максимума |
| `cold_tolerance`, `hot_tolerance` | 0.3 / 0.3 | Гистерезис в °C; неотрицательные, хотя бы один больше нуля |
| `precision` | 0.1 | Точность и шаг: 0.1, 0.5 или 1 |
| `sensor_timeout` | 0 | Допустимый возраст сообщения датчика, секунды; 0 отключает |
| `target_temp` | сохранённая / 20 | Начальная цель в °C |
| `initial_hvac_mode` | сохранённый / off | `heat` или `off` |
| `initial_preset` | сохранённый / away | `comfort`, `eco`, `away` или `sleep` |

## Разработка

```sh
python3.14 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/ruff check .
.venv/bin/ruff format --check .
.venv/bin/pytest -q
```

Тесты работают с настоящим Core HA и состояниями датчика/службами реле в памяти, без управления реальными радиаторами. Исходник собственной иконки — `assets/icon.svg`; PNG для светлой и тёмной тем включены в `brand/` по [формату локальных изображений HA](https://contributors.home-assistant.io/blog/2026/02/24/brands-proxy-api/).
